# MacroEngine

MacroEngine подставляет текст и запускает действия по набранным сокращениям и сочетаниям клавиш. Работает из системного трея, без аккаунтов и облака. Правила можно ограничить конкретными программами: одно и то же `!db` в AutoCAD вызывает команду, а в остальных окнах не срабатывает.

## Быстрый старт

1. Запустите `MacroEngine.exe` — в трее появится иконка.
2. Кликните по иконке левой кнопкой — откроется редактор.
3. Нажмите **Новый**, впишите сокращение (например `!mail`) и текст, который должен его заменить.
4. Нажмите **Сохранить** (`Ctrl+S`) — правило сразу начинает работать.
5. В любом окне наберите `!mail` — сокращение заменится текстом.

Начинайте сокращения с `!` или `@`: так они не сработают случайно посреди обычного слова.

## Триггеры

Раздел «Когда срабатывает» в редакторе задаёт, как запускается правило.

| Способ | Как сработать | Пример |
|---|---|---|
| Набираю текст | набрать сокращение в любом поле ввода | `!tel` |
| Нажимаю сочетание | нажать сочетание клавиш | `Ctrl+Alt+M`, `F8` |
| Аккорд + буквы | зажать 2–3 модификатора и, не отпуская, набрать буквы | `Ctrl+Alt` и `gm` |

Набранное сокращение стирается и заменяется результатом. Нажатое сочетание до программы не доходит.

Сочетание должно содержать `Ctrl` или `Alt`; F-клавиши можно назначать без модификаторов. Системные сочетания Windows (`Ctrl+C`, `Ctrl+S`, `Alt+Tab` и подобные) назначить нельзя — MacroEngine их никогда не перехватывает.

Во время набора аккорда в углу экрана видна подсказка с уже набранными буквами.

## Что делает триггер

| Действие | Значение |
|---|---|
| Вставить текст | текст, можно с токенами — см. «Токены» |
| Вставить форматированный текст | RTF-разметка или путь к `.rtf`; вставляется через буфер обмена, исходное содержимое буфера восстанавливается |
| Выполнить макрос | имя макроса со вкладки «Макросы» |
| Запустить программу | программа и аргументы, например `notepad.exe C:\notes.txt` |
| Открыть папку или файл | путь, открывается в проводнике |
| Выполнить команду или скрипт | команда, как в командной строке: `python C:\scripts\job.py` |
| Загрузить LISP в AutoCAD | путь к `.lsp`, `.fas` или `.vlx` |

Для путей есть кнопки **Файл…** и **Папка…**, для макроса — список и предпросмотр шагов.

## Токены

Токены вставляются в текст кнопками под полем «Текст для вставки» и заменяются в момент срабатывания.

| Токен | Результат |
|---|---|
| `{date}` | 19.10.2026 |
| `{time}` | 21:30 |
| `{datetime}` | 19.10.2026 21:30 |
| `{datetime:yyyy-MM-dd}` | 2026-10-19 — любой формат после двоеточия |
| `{year}` | 2026 |
| `{clipboard}` | текст из буфера обмена |
| `{cursor}` | здесь окажется курсор после вставки |
| `{input:Номер проекта}` | перед вставкой спросить текст |
| `{choice:Да\|Нет\|Не применимо}` | перед вставкой предложить выбор |

Для `{input}` и `{choice}` MacroEngine показывает своё окно, а потом возвращает фокус в исходную программу — если вы за это время не переключились в другое окно.

## Где работает

По умолчанию правило работает **везде**. Чтобы ограничить его, выберите «Только в выбранных программах» и добавьте программы: **Добавить…** показывает открытые сейчас окна, там же можно ввести имя вручную.

Программа узнаётся по имени процесса (`acad`, `winword`, `chrome`), классу или части заголовка окна, без учёта регистра.

Ссылка **Исключить…** добавляет программы, где правило срабатывать не должно, — например, везде, кроме браузера.

Фильтр над списком триггеров показывает правила одной программы.

## Макросы

Макрос — последовательность шагов, которую можно повесить на любой триггер. Макросы создаются на вкладке «Макросы», шаги добавляются ссылками над полем или вписываются вручную, по одному на строку:

```text
type текст для ввода
key Ctrl+S
sleep 500
click 120,300
dclick 120,300
rclick 120,300
run "C:\Program Files\Tool\tool.exe" --argument
```

Пустые строки и строки, начинающиеся с `#`, пропускаются. Если шаг не распознан или завершился ошибкой, макрос останавливается — следующие шаги не выполняются вслепую.

При переименовании макроса ссылки на него в триггерах обновляются сами. Под именем видно, какие триггеры его запускают.

## Редактор

| Клавиши | Действие |
|---|---|
| `Ctrl+S` | сохранить триггеры и макросы |
| `Ctrl+N` | новый триггер или макрос |
| `Ctrl+D` | дублировать триггер |
| `Ctrl+F` | поиск по триггерам |
| `Delete` | удалить выбранное в списке |

Ошибки и конфликты видны сразу: красная полоса — правило не сохранится, пока его не исправить; оранжевая — такой же триггер уже есть и сработает только один из них. Удаление можно отменить кнопкой **Вернуть** в уведомлении внизу.

## Трей

Левый клик по иконке открывает редактор. Правый — меню:

- **Запустить / Остановить** — включить или выключить перехват клавиатуры;
- **Остановить текущее действие** — прервать выполняющийся макрос или вставку;
- **Автозапуск при входе в Windows**;
- **Справка**, **О программе**, **Открыть папку данных**;
- **Проверить обновления** — или **Обновить до vX**, когда новая версия найдена;
- **Диагностическое логирование** — подробный журнал для поиска проблем.

## Обновления

MacroEngine раз в день проверяет, не вышла ли новая версия, и сообщает об этом в меню трея и в окне «О программе». Проверить вручную можно там же; автоматическую проверку можно выключить.

**Обновить** скачивает новую версию со страницы релизов на GitHub, сверяет контрольную сумму SHA-256 и заменяет файлы программы. Если сумма не совпала или что-то пошло не так, установка отменяется, а старые файлы остаются на месте. После установки нажмите **Перезапустить** — окно настроек перед этим нужно закрыть, чтобы не потерять несохранённые правки.

Ваши триггеры, макросы и настройки при обновлении не затрагиваются. Бета-версии получают и бета-обновления, стабильные — только стабильные.

Если программа лежит в папке без прав на запись (например, `Program Files`), установите обновление вручную со страницы релиза.

## Данные и резервные копии

Изменяемые файлы лежат в `%LocalAppData%\MacroEngine`:

```text
config\triggers.json   триггеры (+ .bak — последняя исправная копия)
config\macros.json     макросы  (+ .bak)
logs\macroengine.log   журнал
state\                 служебные отметки и настройки обновлений
```

Пути можно посмотреть и открыть в окне «О программе».

**Портативный режим.** Чтобы хранить всё рядом с EXE (например, на флешке), создайте пустой файл `.portable` рядом с `MacroEngine.exe` до первого запуска.

Перед сохранением JSON проверяется и пишется через временный файл. Если основной файл повреждён, MacroEngine загружает `.bak` и восстанавливает рабочую копию. Конфиги можно править и вручную — изменения подхватываются на лету.

## Безопасность выполнения

Одновременно выполняется не больше одного действия. Если MacroEngine занят, новый запуск отклоняется, а не встаёт в скрытую очередь, — старое действие не выполнится неожиданно позже в другом окне.

Каждое действие привязано к окну, в котором сработал триггер. Если активное окно сменилось, ввод прекращается.

Результат ввода проверяется. Если Windows его заблокировала — например, программа запущена с правами администратора, — MacroEngine покажет ошибку вместо тихого частичного выполнения.

Внутри окон самого MacroEngine триггеры не срабатывают.

## Приватность

Обычный журнал **не записывает** набранные символы, значения подстановок, содержимое буфера обмена, команды и тексты макросов.

Диагностическое логирование выключено по умолчанию. В этом режиме журнал может содержать коды клавиш, раскладку и сведения об активном окне — включайте его только на время поиска проблемы.

Кнопка **Копировать диагностику** в окне «О программе» копирует только версию, ОС, режим хранения и пути к служебным файлам — без ваших триггеров и значений. Проверка обновлений обращается только к GitHub и не передаёт ничего, кроме номера версии в заголовке запроса.

## Если что-то не работает

- **Триггер не срабатывает.** Проверьте, что движок запущен (меню трея), правило сохранено и подходит текущей программе — раздел «Где работает».
- **В одной программе не работает ничего.** Скорее всего, она запущена от администратора: запустите MacroEngine с теми же правами.
- **Срабатывает не то правило.** Ищите оранжевую полосу в списке — у двух правил один и тот же триггер.
- **Обновление не устанавливается.** Текст ошибки виден в окне «О программе». Новую версию всегда можно скачать вручную со страницы [релизов](https://github.com/Aev199/MacroEngine/releases).
- **Нужна помощь.** Включите диагностическое логирование, повторите проблему и приложите журнал и диагностику из окна «О программе».

## Для разработчиков

Сборка и тесты:

```powershell
dotnet test MacroEngine.Tests/MacroEngine.Tests.csproj -c Release
dotnet publish MacroEngine/MacroEngine.csproj -c Release -r win-x64 `
  --self-contained true -p:PublishSingleFile=true -o artifacts/win-x64
```

Выпуск версии: поднимите `<Version>` в `MacroEngine/MacroEngine.csproj`, влейте изменения и поставьте тег с той же версией:

```powershell
git tag v0.6.0-beta.1
git push origin v0.6.0-beta.1
```

Без тега то же самое делается из браузера: **Actions → Build → Run workflow** на `master` с включённым `publish_release` — тег создастся сам.

GitHub Actions соберёт и протестирует сборку, проверит, что тег совпадает с версией проекта, и опубликует релиз с `MacroEngine-<версия>-win-x64.zip` и `SHA256SUMS.txt`. Версии с суффиксом (`-beta.1`) публикуются как пре-релизы. Именно эти два файла ищет встроенное обновление.
